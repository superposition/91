# Held controls, keys and encoders

The production `input()` path now uses `fm1-app::input` when `EN_RUST_APP=1`.
The original C function remains selectable with the flag off. Rust handles
button edges and holds, saver wake consumption, shift-key ownership, FX taps
and latches, note down/up routing, sequencer and progression keys, Songbook
controls, all seven encoders, and queued piece/set-list transitions. The
existing queued set-list retry retains the requested tempo glide on Busy.

`Port::with_ui` and `Port::with_cache` create short state loans. Queries,
messages and application effects occur only after those loans end. The FFI
adapter retains raw pointer tuples rather than an exclusive reference while
calling C. Engine observations copy bounded published CPU0 scalars, or the
initialized ten-byte Songbook settings publication, under the named physical
IRQ-state hooks. IRQ state is restored before Rust policy, metadata lookup,
text formatting or effects. No worker-private sample span is inspected.

Two separate caller-owned cache cells replace the old function statics:
`u32` completed-flex generation and `u8` held-flex state. Their five logical
bytes are unchanged; there is no new mutable payload, framebuffer or counter.
Fixed key maps and routing descriptors are immutable. Adopted-compiler link
gates remain responsible for actual target ROM/RAM and stack measurements.

The private callback tags are generated by `tools/ui_input_abi.py`; `--check`
detects header drift. Null state/cache/callback pointers are rejected before
access. Musical encoder scaling and addition reject signed overflow before
changing the affected value. Physical and browser producer overflow checks
remain at their own platform boundaries. Public WASM exports and saved/wire
formats are unchanged.

`tests/rust_ui_input.sh <R01-source>` verifies all 440 immutable source hashes,
then drives the complete original app/engine, current C0, and Rust-enabled
consumer through 4,096 deterministic input sequences on native and WASM.
It covers all 43 pages, the seven encoder roles, key/button combinations,
press/hold/release timing edges, FX menus, saver wake and queued changes.
Each record contains both rendered PCM blocks, all 193 semantic UI fields,
explicit project/slot/global fields, platform controls, store state, and
hashes of all store payload bytes and the framebuffer. Padding is never
serialized. The reference host is retained whole; the generator only resolves
its source include paths. The corpus is test evidence, never runtime data.

`tests/rust_ui_miri.sh` also executes the actual input adapter under strict
provenance. Callback doubles touch all three disjoint roots, reenter button
and view actions, and verify cache updates, an overflowing encoder rejection,
successful later input, and four missing-argument guards. These are Rust
implementations of the C callback ABI; physical interrupt and DMA behavior
require their separate target qualification.

This checkpoint ports input routing. The existing C effect helpers, MIDI
application policy, remaining controller helpers, page composition and
visualizers remain explicit #15 work. It does not qualify physical controls,
display/audio devices, or interrupt latency.
